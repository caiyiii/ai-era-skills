# Phase 15.10 — AI Drama Production Flow UX Redesign & Workspace Unification

你现在继续开发 AI-Drama-Studio。

当前项目已经完成：

* Phase 15.5
* Phase 15.6
* Phase 15.7
* Phase 15.8
* Phase 15.9

当前项目已经具备完整的 Episode Production Engine：

Project
→ Season
→ Episode
→ Episode Plan
→ Script
→ Storyboard
→ Visual Assets
→ Audio Assets
→ Timeline
→ Render

但是经过真实用户体验后发现：

# 当前最大问题不是生产能力缺失，而是生产流程 UX 混乱。

用户不知道：

* 现在应该做什么
* 下一步应该做什么
* 为什么要跳转到另一个页面
* “生成缺失视觉素材”是什么意思
* 为什么右上角有大量 AI / Generate / Rebuild / Lock / Render 按钮
* 为什么 Script / Storyboard / Assets / Timeline / Render 分散在不同路由
* 为什么一个 Episode 的生产过程不像一条连续的 AI 漫剧生产流水线

本阶段唯一目标：

# 将现有 Episode Production Engine 重构为“线性、清晰、AI 驱动的漫剧生产工作流”。

---

# 一、核心产品原则

本阶段必须遵守以下原则。

## 1. 用户不应该理解底层生产引擎

用户不需要理解：

* GenerationTask
* ProviderResolver
* ProjectAiConfig
* TimelineTrack
* TimelineClip
* RenderJob
* RenderArtifact
* FFmpeg
* FFprobe
* Production Resolver

这些属于系统内部实现。

用户只需要理解：

```text
大纲
↓
剧本
↓
分镜
↓
画面
↓
配音
↓
成片
```

---

# 2. 一个 Episode = 一个完整生产 Workspace

Episode 是用户真正进行生产工作的中心。

不要让用户产生：

```text
Episode
↓
跳 Script
↓
跳 Storyboard
↓
跳 Assets
↓
跳 Timeline
↓
跳 Render
```

这种割裂感。

目标体验：

```text
Episode
│
├── 大纲
├── 剧本
├── 分镜
├── 画面
├── 配音
└── 成片
```

所有生产阶段都属于同一个 Episode Production Workspace。

---

# 3. 生产流程必须是线性的

用户看到的主流程必须统一为：

```text
① 大纲
↓
② 剧本
↓
③ 分镜
↓
④ 画面
↓
⑤ 配音
↓
⑥ 成片
```

不要把：

Timeline

作为一个用户生产阶段。

Timeline 是内部生产引擎。

不要让普通用户主动执行：

```text
Rebuild Timeline
Lock Timeline
```

这些属于成片生成过程。

---

# 4. 当前阶段只有一个主要 CTA

核心交互必须围绕：

# ✨ AI生成

但是不是所有页面都显示同一个“AI生成”。

必须根据当前生产阶段动态显示：

```text
AI生成大纲
AI生成剧本
AI生成分镜
AI生成画面
AI生成配音
AI生成成片
```

如果当前阶段已经完成：

显示：

```text
查看
重新生成
```

而不是继续显示大量不同的 Generate 按钮。

---

# 5. 禁止暴露工程内部动作

普通用户界面禁止出现：

```text
Generate Missing Visual Assets
Rebuild Timeline
Lock Timeline
Create Render Job
Resolve Production
Run Resolver
GenerationTask
RenderArtifact
```

这些属于内部实现。

例如：

内部：

```text
GenerateMissingVisualAssets
```

UI：

```text
✨ AI生成画面
```

内部：

```text
Rebuild Timeline
→ Validate
→ Lock
→ Render
```

UI：

```text
✨ AI生成成片
```

# UX / Routing / Workspace / Production Flow

不是重新开发生产引擎。

# 五、目标 Route Architecture

最终目标：

用户进入 Episode 后：

```text

```

应该成为：

# Episode Production Workspace

内部可以使用：

```text
overview

storyboard

```

这样的 workspace state / child route。

但是用户必须感觉：

# “我一直在同一个 Episode 里生产。”

而不是进入完全不同的模块。

# 六、推荐目标 URL 结构

优先保持：

```text
/projects/:projectId/seasons/:seasonId/episodes/:episodeId
```

作为 Episode Production Workspace 根路由。

如果当前项目已经存在：

```text
/episodes/:id/script
/episodes/:id/storyboard
/episodes/:id/timeline
/episodes/:id/render
```

不要贸然删除。

可以保留兼容 redirect。

例如：

```text
/episodes/:id/script
→ /episodes/:id?step=script
```

或者：

```text
/episodes/:id/script
→ /episodes/:id/script
```

但视觉层必须仍然属于统一 Episode Workspace。

不要为了“统一路由”破坏已有链接。
