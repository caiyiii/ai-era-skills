现在不要进入第五阶段。

在第四阶段 AI Generation Engine v1 基础上增加：

Phase 4.5 — AI Provider Management。

目标：

将目前仅依赖 API 服务端 .env 的 AI Provider 架构升级为可视化 Provider 管理。

重要：

不要破坏现有 AI Generation Engine。

不要修改现有 World CRUD。

不要实现用户登录/注册。

不要实现支付。

不要更换 Monorepo / 技术栈。

==================================================
一、核心架构
==================================================

最终目标：

System Provider
      ↓
User Provider
      ↓
Project Provider

当前因为 User 系统尚未实现：

允许先实现 Project / Development Scope 的 Provider 管理，

但数据库模型必须为未来 User → AIProvider 做好扩展。

不要创建假的复杂用户系统。

==================================================
五、加密配置
==================================================

增加：

AI_ENCRYPTION_KEY

服务端 .env。

要求：

AES-256-GCM 或项目中安全可靠的等价方案。

不要自己实现不安全的加密算法。

AI_ENCRYPTION_KEY 缺失时：

开发环境明确报错。

生产环境禁止启动 Provider 管理功能。

不要把 encryption key 写入日志。
