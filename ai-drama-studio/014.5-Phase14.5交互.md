# Phase 14.5 — Production Workflow & UX Refactor

这是 AI Drama Studio 的第 14.5 阶段。

==================================================
一、阶段目标
==================================================

本阶段不是增加新的 AI 能力。

本阶段的最高优先级目标：

把当前已经存在的：

Project
→ World
→ Characters
→ Story Bible
→ Season
→ Episode
→ Script
→ Storyboard
→ Image
→ Video
→ Voice
→ Music
→ SFX
→ Timeline
→ Render

重新组织成：

“普通创作者不需要阅读开发文档，也知道下一步应该做什么”的生产工作流。

当前项目已经存在大量真实业务能力。

但是经过真实用户走查，发现：

1. Season / Episode / Script 三者职责不够清晰。
2. Episode 与 Script 页面显示的数据高度重合。
3. Storyboard 与 Episode / Script 之间频繁跳转。
4. 用户容易在 Season / Episode / Script / Storyboard 之间迷失。
5. Season AI 拆解剧集在已有 Episode 时无法 Apply。
6. “该 Season 已存在剧集”导致 AI 拆解无法应用，这属于错误的产品交互。
7. Images / Videos / Voices / Music / SFX / Timeline 目前更像独立全局模块，而不是 Episode Production Pipeline 的一部分。
8. 用户不知道什么时候应该进入 Timeline。
9. 用户不知道什么时候可以 Render。
10. 当前 UI 更像“数据库模块导航”，而不是“创作者生产工作台”。

本阶段必须解决以上问题。

==================================================
二、核心产品原则
==================================================

必须建立以下用户心智模型：

Season = “这一季讲什么”

Episode = “这一集讲什么”

Script = “这一集具体怎么讲”

Storyboard = “这一集具体怎么拍”

Assets = “这一集需要的画面和声音素材”

Timeline = “把已经生成的素材编排起来”

Render = “把已经锁定的 Timeline 输出为成片”

必须严格保持：

Season
↓
Episode
↓
Script
↓
Storyboard
↓
Assets
↓
Timeline
↓
Render

不要让：

Episode = Script

不要让：

Script = Storyboard

不要让：

Storyboard = Asset

不要让：

Timeline = Script / Storyboard / Asset

Timeline 仍然只是 Composition / Orchestration Layer。

Phase 13 已明确：
Timeline 不是 Script / Storyboard / Asset 的替代品。

继续保持：

Script
↓
Storyboard
↓
Assets
↓
Timeline
↓
Composition Preview
↓
Render

不要改变底层 Timeline 数据模型。

三、绝对禁止
==================================================

本阶段：

禁止重建 Monorepo。

禁止更换技术栈。

禁止 prisma migrate reset。

禁止 DROP TABLE。

禁止删除历史数据。

禁止删除历史 migration。

禁止修改历史 migration。

如果需要数据库变化，只允许新增 migration。

禁止重新设计 Timeline 数据模型。

禁止删除 EpisodeTimeline / TimelineTrack / TimelineClip。

禁止删除 Render Job。

禁止删除现有 AI Provider。

禁止新增无必要 Provider。

禁止新增 AI Generation 能力。

禁止为了 UX 重写已经稳定的 AI Generation Service。

禁止修改现有 AI Generation 的 capability fallback 规则。

禁止：

IMAGE fallback TEXT

VIDEO fallback IMAGE

TTS fallback CHAT

MUSIC fallback TTS

SFX fallback TTS

Timeline 不调用 AI。

Timeline Build 不调用 AI。

Render 不应该偷偷触发 AI Generation。

状态展示

==================================================

十三、Next Step Engine
==================================================

必须增加一个前端可复用的：

Production Progress / Next Step 计算逻辑。

不要把逻辑散落在多个页面。

建议：

packages/core

或者：

packages/utils

增加：

getEpisodeProductionProgress()

getEpisodeNextStep()

逻辑示例：

如果没有 Script：

nextStep = SCRIPT

如果 Script Ready，但没有 Storyboard：

nextStep = STORYBOARD

如果 Storyboard Ready，但缺少 Visual：

nextStep = VISUALS

如果 Visual Ready，但缺 Voice：

nextStep = VOICE

如果 Voice Ready，但缺 Music/SFX：

nextStep = AUDIO

如果素材齐全，但没有 Timeline：

nextStep = TIMELINE

如果 Timeline 存在但未 LOCKED：

nextStep = TIMELINE_REVIEW

如果 Timeline LOCKED，但没有成功 Render：

nextStep = RENDER

如果 Render 成功：

nextStep = COMPLETE

注意：

不要要求每一项都必须存在才能查看下一项。

这是：

“推荐下一步”

不是：

“强制工作流锁”。
