# Phase 14.5 — Episode Production Workflow Refactor v2

这是 AI Drama Studio 的 Phase 14.5。

本阶段不是新增一个孤立功能。

本阶段的最高优先级，是彻底解决当前产品从：

World
→ Character
→ Story Bible
→ Season
→ Episode
→ Script
→ Storyboard
→ Assets
→ Timeline

之间的用户操作流程混乱问题。

==================================================
一、当前发现的问题
==================================================

当前项目虽然已经具备：

World
Character
Story Bible
Season
Episode
Script
Storyboard
Image
Video
TTS
Music
SFX
Timeline

但实际用户操作时存在严重的信息架构问题：

1. Season / Episode / Script / Storyboard 的职责边界不清晰。

2. 在 Season 中使用 AI 拆解 Episodes 后，
   点击某一个 Episode，
   用户仍然容易回到 Season Planning / Season Planner。

3. Episode 页面和 Script 页面视觉与数据结构过于相似，
   用户无法明确判断：
   “我现在是在规划这一集，还是在写这一集？”

4. Script 与 Storyboard 的关系不清晰。

5. 用户不知道：
   “什么时候应该生成剧本？”
   “什么时候应该生成分镜？”
   “什么时候开始生成图片？”
   “什么时候生成视频？”
   “什么时候进入 Timeline？”

6. Storyboard、Script、Episode 之间出现互相跳转，
   导致用户感觉三个模块像是在编辑同一份数据。

7. Season AI 拆解存在严重反人类行为：

   当 Season 已经存在部分 Episode 时，
   再次执行 AI 拆解可能被完全阻止。

   例如：

   Season 1 已经存在：

   E01
   E02
   E03

   用户希望继续 AI 拆解：

   E04
   E05
   E06
   ...

   当前系统不应该因为“该 Season 已经存在 Episode”
   就禁止整个 AI 拆解操作。

8. 当前系统缺少一个真正的：

   Episode Workspace

   用户应该进入一个 Episode 后，
   从这一集的规划开始，
   一路完成：

   Episode Plan
   → Script
   → Storyboard
   → Assets
   → Timeline

   而不是在多个全局页面之间跳来跳去。

==================================================
三、核心产品概念
==================================================

必须把整个产品理解成：

“用户正在制作一部 AI 漫剧。”

而不是：

“用户正在操作一堆数据库实体。”

所以 UI 和路由不能仅仅按照 Prisma Model 设计。

必须按照：

用户完成一集漫剧的实际生产流程

设计。

==================================================
四、必须明确的职责边界
==================================================

-----------------------------------------------
1. Season
-----------------------------------------------

Season 的职责：

“这一季讲什么？”

Season 用于：

- 季级故事规划
- Season Arc
- Season Theme
- Season Goal
- Episode List
- Episode 顺序
- Episode 简介
- Season 级 AI 拆解 Episodes

Season 不负责：

- 具体 Scene
- 具体 Dialogue
- Shot
- Image Prompt
- Video Prompt
- Timeline

Season 页面应该让用户理解：

“我正在规划这一季。”

-----------------------------------------------
2. Episode
-----------------------------------------------

Episode 的职责：

“这一集讲什么？”

Episode 必须拥有独立的：

Episode Workspace

Episode Planning 用于：

- 本集标题
- 本集简介
- 本集目标
- 本集核心冲突
- 本集主要角色
- 本集主要场景
- 本集情绪 / 节奏
- 本集开始状态
- 本集结束状态
- 与上一集关系
- 与下一集关系

Episode Planning 不等于 Script。

-----------------------------------------------
3. Script
-----------------------------------------------

Script 的职责：

“这一集具体发生什么？”

Script 应包含：

- Scene
- Scene 顺序
- Scene 地点
- Scene 时间
- Characters
- Action
- Narration
- Dialogue
- Emotion
- Script Blocks

Script 是：

“故事文本 / 拍摄前剧本”。

必须明确：

Episode Plan = 本集讲什么

Script = 具体怎么讲这个故事

-----------------------------------------------
4. Storyboard
-----------------------------------------------

Storyboard 的职责：

“剧本中的内容应该怎么拍？”

Storyboard 应建立：

Script
  ↓
Scene
  ↓
Shot

例如：

Script：

“林玄站在悬崖边，看见天空出现空间裂缝。”

Storyboard：

Shot 001
- Wide Shot
- 天玄山
- 林玄站在悬崖
- Camera movement
- Composition

Shot 002
- Medium Shot
- 林玄抬头

Shot 003
- Close Up
- 林玄眼睛

Shot 004
- Wide Sky Shot
- 空间裂缝出现

必须明确：

Script = WHAT happens

Storyboard = HOW it is filmed

-----------------------------------------------
5. Assets
-----------------------------------------------

Assets 是生产结果：

- Image
- Video
- Voice
- Music
- SFX

它们属于：

Episode Production

而不是新的剧情规划层。

-----------------------------------------------
6. Timeline
-----------------------------------------------

严格遵守 Phase 13 已确定架构。

Timeline 是：

Composition / Orchestration Layer

不是：

Script
Storyboard
Asset

替代品。

Timeline 只引用已有实体。

不要修改 Timeline 架构。

不要把 Script / Storyboard / Asset 内容复制到 Timeline。
